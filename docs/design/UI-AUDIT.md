# Dork Bot UI audit (card 31)

Design, 2026-11-20. Base: main d15cfe1. Brennan: "We need to make sure we have a uniform UI."
The rules this audit points at are in `UI-KIT.md` (LOCKED). Rule ids (K1, K2 ...) are the kit's section numbers.

## How this was done
- `npm run test:layout` at d15cfe1: 280/280 screens clean. Screenshots read from `artifacts/layout/` (git-ignored, not committed): iPhone, Duo folded (`duo-closed`), Duo open portrait and landscape, plus the `desktop--` and `ui--desktop-*` shots.
- Every screen in the ask was read in code and in at least one screenshot: bot list, 1:1 chat, group chat, Chats, Work, Routines, Routine results, Usage, Connectors, Look, Model, Notifications, New bot, New group, bot sheet, menus, dialogs.
- **Limit:** the layout harness is a plain browser, so `isDesktop` is false there. Desktop-only code (the ⚙ gear, the desktop Overlay panel, `RoomNew` footer buttons, desktop Dialogs) was checked from code, plus the `ui--desktop-*` shots that do run the desktop chrome. Rows marked "code only" have no screenshot yet. The layout test cannot see the ⚙; kit guard G1 and G4 catch it from source.
- Evidence tags: `shot` = seen in a screenshot, `code` = read in source.

## Notes by screen (what was checked)

- **Bot list**: matches REVIEW.md fix 1 (large title, ⋯ and compose icons, rows). Only drift: row ⋯ glyph (17), empty-state disc (24).
- **1:1 chat**: the reference header. Everything else should look like it.
- **Group chat**: rows 1-7, 36-37.
- **Chats / Work / Routines / Routine results**: sheet header is shared; bodies drift (24-26, 29-30, 22).
- **Usage**: own page header (4, 8), own primary button (12), `↻` glyph (19).
- **Connectors / Model / Look / Notifications / New bot**: share Group rows and switches. Drift in the check marks (20), fields (27-28), commit placement (10).
- **Menus and dialogs**: 33-34.

## Priority (what hurts most, in order)
1. Group chat header and rooms vs 1:1 (rows 1-7, 36-37). This is the gear Brennan saw.
2. Icons: three files plus text glyphs (18-20).
3. Buttons built by hand (11-15).
4. Empty, loading and error states: six, four and four variants (24-26).
5. Fields, chips and padding (22, 27-29).
